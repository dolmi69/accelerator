# Co-Founder.AI (accelerator)

Этот файл Claude Code читает в начале каждого чата. Здесь общие знания о проекте: что делаем, кто делает, как устроен код. Если факты устарели, Claude обновляет этот файл и коммитит его вместе с работой.

## Что это

**Co-Founder.AI** (репозиторий `dolmi69/accelerator`, команда MBB) — AI-акселератор для начинающих основателей стартапов. Основатель своими словами описывает идею, а ассистент **Бруно** (медведь-маскот, «сооснователь и наставник») превращает её в картину проекта и проверяемые следующие шаги. Решения принимает основатель. С beta 0.6 Бруно ещё и собирает рабочие прототипы («Bruno Forge»).

- **Аудитория** (`docs/value_proposition.md`): студенты и начинающие основатели в университетских акселераторах, стадия идеи или раннего MVP. Главный сценарий — подготовка к встрече с куратором. Покупатели: университеты, инкубаторы.
- **Цель команды — деньги**: проект должен приносить доход и окупать себя.
- **Статус (2026-10-08):** MVP, main = `9c0ff41` «beta 0.6 - Bruno Forge». В `Andrey` поверх него «Панель акул» и Bruno2/2.1 (наставник), коммиты «Bruno2» и «Bruno 2.1» пока не запушены. Демо запланировано на **2026-10-20**. Видение продукта в `docs/product_direction.md`: цикл гипотеза → эксперимент → доказательство → изменение радара, интеграция с GitHub Issues (пока не сделана).
- **Весь UI на русском.** Стиль Бруно следует правилам stop-slop: без клише и канцелярита, один вопрос за реплику, никогда не угадывать пол основателя, никогда не выдумывать цифры.

## Как работаем с git

- Каждый программист работает в ветке, названной его именем. В `main` вливают **только Артём или Эльдар**.
- Claude коммитит и пушит только в ветку текущего пользователя, сам ничего не мержит в main и не открывает такие мержи.
- Чтобы подтянуть свежий main, его мержат в свою ветку.
- Кто сейчас за клавиатурой, видно по `git config user.name`.

### Работа с двух устройств (Андрей: ПК и ноутбук)

## Фичи → файлы (всё в `founder/`)

- **Бруно-наставник (Bruno2, ветка `Andrey`):** `services/mentor.py`. Перед ответом в чате-сооснователе один запрос (без строгой схемы) выбирает линзу (сезонность, холодный старт, частота, кто платит, замена, первые клиенты, деньги), мысль, главный пробел, ход (deepen/idea/calc/contradiction/experiment/insight, не больше двух deepen подряд), вопрос и заметки `notes` только по темам последней реплики → картина проекта (`ProjectPicture`: 7 тем, статусы факт/догадка/неизвестно, анкета заполняет её сразу). Пустой план повторяется один раз; вопрос, похожий на уже заданный (≥50% общих основ слов), отбрасывается, и ответ выбирает новый. Режимы ответа по реплике: «давай подумаем / идеи / слабые места» → рассуждение вслух + 3 идеи (`MentorIdea`, кнопка «Проверить это» → `BrunoTask`), «подведи итог встречи» → итог. Новая встреча начинается с прошлого пробела и открытого задания (без запроса к модели). Подсказки-ответы под полем ввода. Выключатель `BRUNO_MENTOR_PLAN` (в `manage.py test` всегда выключен). Тесты: `founder/test_mentor.py`; прогон: `bruno_eval -s mentor` и сценарии на реальных идеях `-s real_coffee -s real_ege -s real_shifts -s real_dresses`.
  Уроки GigaChat: плоскую схему он всё равно вкладывает (`{"update1": {"team": {...}}}`, `{"money": {"update1": {...}}}`), поэтому `parse_updates` ищет text/status на любой глубине; иногда шлёт два JSON подряд (`model_json` их склеивает); без линзы мысль выходит общей («подтвердить спрос»); без расчёта Python в плане выдумывает прибыль; без списка «уже спрашивал» задаёт один вопрос по кругу. Отдельный запрос картины после ответа держал чат ещё 5–15 с, поэтому картина пишется в том же запросе, что и план. Ответ: медиана ~6 с по 23 репликам на GigaChat, длинные ответы и первый после запуска до ~18 с. Вопрос в плане необязателен (в идеях и итоге GigaChat оставляет его пустым); «разборы сочинений» больше не считаются просьбой о разборе; изменившаяся цифра по той же теме («15 платящих» → «25») отмечается заметкой `number_change`.

## Стек и AI

- Python 3.14, Django 6, Channels/Daphne; SQLite (PostgreSQL через `DATABASE_URL`); Redis/Valkey для событий. Tailwind собран заранее. Шаблоны — длинные однострочники.
- `AI_PROVIDER`: demo | gigachat | cloudru | openai | anthropic.
- Бруно в проде = GigaChat-3-Pro на `api.giga.chat`. Если он недоступен, на 5 минут автоматически переключается на `gigachat.devices.sberbank.ru` + GigaChat-2-Max, который игнорирует JSON-схему, поэтому ответы парсятся терпимо (`model_json.py`). Личный ключ GigaChat даёт 429 на параллельные запросы: **никогда не запускать два eval одновременно**.
- Qwen использует `CLOUDRU_API_KEY`. Ключи только в `.env` (в gitignore), сертификат Минцифры в `certs/`.

### «Бруно уже выполняет ваш запрос» (исправлено в `Andrey` 2026-10-08, в main ошибка осталась)
Причина: под ASGI (Daphne) Django отменяет обработку запроса, когда клиент уходит со страницы, и `process_response` middleware не вызывается. Если уйти со страницы во время долгого AI-запроса (оценка радара ~20 с, задачи, разбор питча, карточка), блокировка «1 AI-запрос на аккаунт» висела 10 минут и чат отвечал 429. Исправление в `security_middleware.py`: после выдачи блокировки middleware сам вызывает view в `process_view` и освобождает блокировку в том же потоке (`guard_lease`). Тест: `test_lease_released_when_process_response_is_skipped`. Воспроизведено и проверено вживую на 8000/8001.
