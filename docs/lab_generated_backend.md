# Бэкенд, который пишет модель

В сыром тесте появился выбор «Сайт с бэкендом» (по умолчанию в интерфейсе) / «Статический макет».
Готовые бизнес-модули, Forge/BrunoApp, сохранённые шаблоны и бесплатные локальные правки остаются отключены.

## Генерация

Один оплачиваемый запрос возвращает все исходники: index.html, app.py и необязательные assets/*.css/js.
app.py — самостоятельное WSGI-приложение на стандартной библиотеке Python. Модель пишет бизнес-логику,
SQL, проверку данных, регистрацию, сессии, API и взаимодействие интерфейса с ними.
Хост не содержит готовых каталога, аккаунтов, бронирования или дизайнерских блоков.
Если нужен каталог, инструкция просит модель добавить 3 тематических демонстрационных записи
только в пустую таблицу и показывать их через API; это инструкция, а не гарантия качества ответа.

Исходники хранятся в LabSiteVersion.backend_files. Правка передаёт модели все исходники выбранной
версии. Неполный JSON, синтаксическая ошибка, неподходящие пути, секреты или отключённые мосты
отклоняются без автоматического платного повтора. Статический путь и старые Django-версии сохранены.

## Запуск и данные

Изолированный автозапуск модельного Python пока реализован для macOS через sandbox-exec.
На других системах запуск отклоняется; можно скачать исходники и отдельно запускать локальный проект.
Без изоляции генератор не исполняет код в процессе Co-Founder.AI.

Каждая версия запускается отдельным процессом на loopback-порту, на другом hostname относительно
платформы. Среда не наследует ключи, PYTHONPATH, настройки Django или основную БД.
Разрешены чтение стандартной библиотеки/своих исходников, запись в свою папку data, приём
соединений на единственном локальном порту. Исходящие соединения, fork и доступ к файлам
платформы запрещены ОС. Есть ограничения CPU, размера файлов, числа файловых дескрипторов,
размера HTTP-запроса и ответа. Лимиты среды исполнения не являются лимитами токенов.

SQLite лежит в .runtime/lab-backends/<startup>/generated-projects/<version>/data/data.sqlite3.
Остановка/перезапуск сохраняет базу. При первом запуске дочерней версии SQLite backup копирует
данные выбранной исходной версии. Ветки истории имеют независимые базы; последующие записи
в новую версию не появляются в старой. Неуспешный запуск восстанавливает прежнюю базу версии.
Удаление стартапа останавливает процесс и убирает его локальные базы штатным путём удаления проекта.

Host/Origin проверяются хостом; чужие cookies и Authorization не передаются приложению.
Cookies приложения имеют префикс lab_, Domain не разрешён. CSP ограничивает соединения своим
origin. Статические файлы обслуживаются только из явного списка расширений/путей.
Рантайм проверяет запуск, но не доказывает правильность всей бизнес-логики модели: функции
сгенерированного приложения нужно проверять сценариями, особенно права и пересечение броней.

ZIP содержит только исходники и минимальный start.py. Требуется Python 3.11+, без pip.
Публичный хостинг/внешние платежи/email/API сейчас не подключены. На этапе публикации нужен
отдельный runtime и проверка сгенерированного кода; кнопка публикации для этого вида скрыта.

## Проверки

founder.test_generated_backend проверяет сохранение/наследование исходников, ошибку генерации,
экспорт без базы/секретов и настоящий процесс с SQLite: запись, повторный запуск, копирование
версии, Host/Origin, запрет чтения/записи файлов платформы, исходящих соединений и fork.

## Поэтапная сборка

`LAB_BACKEND_STAGED_GENERATION=1` включает 2 отдельных модельных запроса:
app.py с описанием API, затем index.html/CSS/JS под готовый сервер.
Объединённая версия сохраняется только после успешного завершения обоих ответов.
Каждый этап платный; повторения провайдера не выполняются автоматически.

Успешный первый этап после проверки синтаксиса и отчёта сохраняется в приватный
файл с правами 0600 в `.runtime/lab-generation-stages/<user>/<startup>/`.
При сбое интерфейса повтор того же запроса с той же исходной версией и профилем
модели использует завершённый сервер и запрашивает только интерфейс. Учёт usage
сохраняет оба исходных request_id и не создаёт повторную оплату серверного этапа.
Другой пользователь, проект, промпт, источник или модель имеют другой checkpoint.
Успешная сборка удаляет checkpoint; удаление стартапа очищает файлы всех соавторов.

Checkpoint содержит только завершённый и проверенный ответ: содержимое, остановленное
фильтром или обрывом потока, не восстанавливается и не используется. Это собственный
код данного запроса, а не сохранённый бизнес-модуль или дизайнерский шаблон.

Два меньших ответа позволяют сохранять завершённый этап и уменьшить объём одного
ответа; они не гарантируют устранение `content_filter` у Ofox. Не нужно обходить фильтр,
отключать проверки завершения или выдавать частичный код за работающий сайт.
Повторный `content_filter` требует диагностики со стороны поставщика API.
