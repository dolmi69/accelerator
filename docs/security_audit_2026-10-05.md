# Проверка безопасности и устойчивости — 5 октября 2026

## Что проверено

Код Django, настройки развёртывания, вход и регистрация, права на проекты и
переписки, публикация карточек, загрузки и аватары, ответы ИИ, WebSocket,
история чатов, зависимости и история Git. Проверки атак выполнялись на тестовой
базе с искусственными данными. Отдельно проверена доставка сообщений между
двумя работающими локальными серверами; временные аккаунты и сообщения удалены.

Это ограниченный аудит конкретных сценариев, а не гарантия отсутствия всех
уязвимостей или замена независимого пентеста и нагрузочного тестирования.

## Исправлено

### 1. Частые запросы и одновременные обращения к ИИ

Раньше HTTP-запросы не имели общих ограничений. Добавлены счётчики в базе,
работающие между процессами и вкладками:

- вход: 30 попыток за 15 минут с одного IP;
- регистрация: 10 запросов за 15 минут с одного IP;
- изменения данных: 120 POST-запросов в минуту на аккаунт;
- чат, радар, карточка, задания и разбор питча: 12 запросов в минуту и 200
  в сутки на аккаунт, настраиваются в `.env`;
- одновременно на аккаунт выполняется одна операция ИИ. Блокировка снимается
  при завершении/ошибке/закрытии потока; после аварии истекает через 10 минут;
- WebSocket: общий предел 360 входящих событий в минуту на аккаунт,
  сохраняющийся при переподключении, дополнительно к прежнему лимиту соединения.

При превышении возвращается 429 с `Retry-After`. Обычные формы получают
понятную HTML-страницу с кнопкой возврата; чат продолжает получать JSON.
Страница ошибки не обращается к базе, не кешируется и не принимает внешнюю
ссылку возврата из заголовка запроса. Сбой счётчика запрещает новую
дорогую операцию. Обычный сервер не доверяет присланному `X-Forwarded-For`;
Telegram-сервер доверяет заголовку Cloudflare только за локальным туннелем.
Миграция: `0009_request_protection`.

### 2. Потеря текста и повторная отправка в чате

Раньше поле ввода очищалось до ответа сервера. Теперь отклонённая отправка
сохраняет текст и выбранный файл. Истёкшая сессия и ошибка HTTP показываются
понятно. Двойное нажатие не создаёт второй запрос. При неоднозначном сетевом
сбое пользователь видит ссылку обновления и предупреждение проверить историю
перед повторной отправкой. После принятия запроса сообщение уже находится в
базе и сохраняется при ошибке модели. Ожидание в браузере ограничено 120 секундами.

### 3. Недопустимые загрузки и ответы

Добавлена остановка файловой загрузки по реально полученным байтам (5 МБ
суммарно); для вложения в чат остаётся предел 2 МБ. Ограничены размер обычных
полей, число полей/файлов, длина описаний. Пустой текст, двоичные данные под
расширением TXT и JSON глубже 64 уровней отклоняются. Глубина JSON также
проверяется в WebSocket и структурированных ответах ИИ. Некорректные части
потока и статус источника радара больше не вызывают необработанные ошибки.
Ответ чата дополнительно ограничен 60 тысячами символов.

### 4. Загрузка переписок

Чат с Бруно загружает 50 сообщений вместо всей истории; есть переход к более
ранним сообщениям. Ссылки из радара открывают страницу нужного сообщения.
Список личных диалогов получает последнее сообщение и непрочитанные счётчики
одним запросом вместо двух дополнительных запросов на каждый диалог.
Тест сравнивает число запросов для одного и двенадцати диалогов.
Разбор длинного питча загружает не больше 100 последних сообщений и явно
передаёт модели, что анализируется только последний фрагмент.

### 5. Сообщения между сайтом и Telegram

Раздельные серверы на портах 8000 и 8001 использовали память своих процессов.
Из-за этого событие из одного процесса не доходило до второго сразу.
Подключён общий Valkey 9.1.2, совместимый с Redis, только на `127.0.0.1:6387`.
Переписки по-прежнему хранятся в SQLite, Valkey доставляет временные события.

В реальном запуске выявлена также несовместимость стандартного тайм-аута
redis-py 8 с ожиданием Channels: соединения обрывались при простое. Установлен
явный тайм-аут 15 секунд при блокирующем ожидании Channels 5 секунд.
[Описание проблемы в репозитории Channels](https://github.com/django/channels_redis/issues/422).

`start_shared_events.py` запускает локальный Valkey при необходимости;
его вызывают `start.command` и `start_telegram_local.py`. Бинарник и данные
исполнения находятся в игнорируемых `.tools/` и `.runtime/`. Для другого
компьютера нужно установить Redis/Valkey и настроить `REDIS_URL`.
Сборка на этом Mac выполнена из официального тега Valkey 9.1.2.
Проверка свободного порта Telegram теперь допускает остаточные соединения
`TIME_WAIT` после остановки сервера, но продолжает обнаруживать активный
сервер. Это убирает ложную ошибку занятого порта при быстром перезапуске.

### 6. Настройки и зависимости

При `DJANGO_DEBUG=0` включены HTTPS-перенаправление, Secure cookies и HSTS
с коротким сроком. Доверие заголовку HTTPS-прокси включается отдельно.
Локальный HTTP на порту 8000 продолжает работать; публичный Telegram-origin
использует отдельные настройки с выключенным DEBUG.

В установленном pip 26.1.1 найдены два известных предупреждения безопасности;
pip обновлён до 26.2.1. Повторная проверка всех 56 установленных пакетов через
pip-audit не обнаружила известных уязвимостей. Это результат используемой
базы advisories на момент проверки.

### 7. Стили без компиляции в браузере

Внешний `cdn.tailwindcss.com` заменён готовым локальным CSS. На проверенной
версии вместо загрузки компилятора размером 407 279 байт браузер получает
файл стилей размером 6 000 байт. Это сравнение размеров файлов до сжатия,
а не измерение общего ускорения страницы. Стили пересобираются разработчиком;
для запуска сайта Node.js не нужен. Шрифты Google пока остаются внешними.

В инструментах сборки есть одно известное предупреждение высокой серьёзности:
`braces` 3.0.3 может переполнить стек при глубоко вложенном glob-шаблоне.
[GitHub advisory GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
не указывает исправленной версии. В этой конфигурации glob-шаблоны заданы
разработчиком в `tailwind.config.cjs`; посетители не передают их в сборку.
Пакет не используется Django и не отправляется в браузер. Предупреждение
не скрыто и требует обновления после выпуска исправления; сборщик нельзя
использовать для недоверенных пользовательских шаблонов будущей лаборатории.

## Результаты проверок

- 106 тестов Django: права, CSRF, изоляция черновиков, XSS-экранирование,
  блокировки, восстановление сообщений, аватары, лимиты, потоки, загрузки,
  пагинация, анкета и контекст Бруно.
- Отдельный тест двух действительно одновременных HTTP-запросов одного
  аккаунта: второй отклонён с 429, провайдер вызван один раз, в истории одна
  пара сообщений, после завершения можно снова отправлять запросы.
- 6 изолированных JavaScript-тестов отправки: HTTP-ошибка, выход из сессии,
  разрыв сети, полный/неполный поток, двойное нажатие. Без внешних зависимостей.
- Проверка реальных серверов: сообщение 8000 → 8001, обратное уведомление
  прочтения и живое соединение после 12 секунд бездействия.
- HTTP-проверка локального сайта и публичной HTTPS-ссылки, Secure cookies,
  `nosniff`, `getMe` бота и соответствие ссылки его кнопки текущему туннелю.
- Главная и чат открыты в браузере. Ошибок JavaScript в просмотренных логах нет.
  После перезапуска проверены профиль проекта и чат с локальным CSS;
  внешний компилятор Tailwind в HTML отсутствует.
- В 155 уникальных проверенных Git-блобах не найдены текущие ключи из `.env`
  или совпадения с проверяемыми шаблонами GitHub/OpenAI/Telegram-токенов.
  Это не проверка всех возможных форматов секретов.
- Bandit: находки только низкого уровня, просмотрены вручную. Вызовы процессов
  используют списки аргументов без shell; оставшиеся сигналы относятся к
  локальному dev-ключу и пустому начальному значению токена.
- `makemigrations --check` и `git diff --check` без замечаний.

## Рабочие данные и запуск

Перед миграцией создана согласованная резервная копия SQLite:
`.runtime/backups/pre-security-20261005-122327.sqlite3` (права 0600).
Миграция применена. После проверки сайт, Valkey, HTTPS-туннель и бот запущены.
Текущая временная ссылка находится в `.runtime/telegram.json`; она меняется
при новом запуске туннеля. Учётные записи и проекты пользователя сохранены.

Обычный запуск: `start.command`; Telegram: `start_telegram.command`.
После изменений Python работающие процессы с `--noreload` нужно перезапускать.
Для проверки тестов отдельно от работающего канала сообщений:

```sh
REDIS_URL='' .venv/bin/python manage.py test --noinput
node --test tests/chat_client.test.cjs
```

После изменения HTML-классов пересоберите CSS и сохраните полученный файл
вместе с изменениями шаблонов. Версии инструментов закреплены lock-файлом:

```sh
pnpm install --frozen-lockfile
pnpm run build:css
```

## Что остаётся перед полноценным публичным запуском

- Сейчас это локальное демо: Django runserver и временный туннель зависят от
  включённого Mac. Нужны постоянный ASGI-сервис, HTTPS-прокси, автозапуск,
  резервные копии вне Mac и наблюдение за ошибками.
- Ограничение тела запроса также нужно настроить на внешнем прокси: ASGI-сервер
  может принять/временно сохранить тело ещё до Django upload handler.
- Лимиты запросов не равны денежному бюджету. Несколько аккаунтов и повторы
  внутри оценивания увеличивают расход. Для платного сервиса нужны учёт токенов,
  бюджет владельца и защита регистрации от массового создания аккаунтов.
- Отключение браузера не гарантирует остановку уже отправленного запроса к ИИ;
  провайдер может продолжить работу и списать токены. Для долгих задач лучше
  отдельная очередь с сохранением состояния и возможностью повторного получения
  результата.
- Полное нагрузочное тестирование не выполнялось. Ограниченные проверки
  одновременных запросов не определяют предельную нагрузку сервиса.
- Два предупреждения `check --deploy` оставлены осознанно: HSTS для всех
  поддоменов и включение в preload-лист нельзя выбирать до определения своего
  домена и настройки HTTPS на всех его поддоменах.
- У ИИ нет доступа к выполнению кода, ключам и чужим проектам через инструменты,
  но устойчивость бизнес-оценок к манипуляциям требует отдельного набора оценок.
  Сообщение основателя не становится независимо подтверждённым фактом.
