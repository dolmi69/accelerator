# Серверный сайт в карточке проекта

В лаборатории откройте «Сохранение и настройки версии», выберите доступ и нажмите
«Добавить в карточку». Для версии `generated` карточка содержит доверенную страницу
запуска, а не HTML модели на домене платформы. Загрузчик автоматически делает POST с CSRF,
повторно проверяет выбранную публикацию и права пользователя.

Рабочий сайт открывается в отдельном origin `lab-<version>.localhost:<port>`.
Код выполняется существующим изолированным macOS worker. Для публикации используется
директория `.runtime/lab-backends/public-<startup>/generated-projects/<version>`.
База редактора не копируется. При смене версии могут переноситься только данные
предыдущей публичной версии. Повторный запуск сохраняет базу посетителей. Публикация
не переключает активный проект редактора и не останавливает его сервер. Скрытие,
смена версии или режима доступа останавливает прежний публичный сервер.

Глобальный лимит числа работающих серверов сохраняется. Сайт автоматически запускается при загрузке видимого предпросмотра карточки. Публикация с приватным доступом доступна только команде
согласно существующей проверке `_published`.

Для `generated` не создаются `LabTestSession`, не подключается трекер кликов,
не выдаются монеты за тест и не вызывается AI-анализ. Старое тестирование статических
прототипов работает как прежде.

## Граница текущей реализации

Это локальный запуск. На удалённом хосте endpoint возвращает 503 с понятным
объяснением, а страница не отправляет посетителя на его собственный localhost.
Для общего интернет-доступа нужны серверная изолированная среда выполнения,
отдельные домены приложений, HTTPS, маршрутизация и управление жизненным циклом.
Нельзя просто снять проверку локального хоста или выдавать модельный HTML с правами
основного домена платформы.

Проверки: `manage.py test founder.test_lab_backend_publication founder.test_lab_testing founder.test_generated_backend`.
