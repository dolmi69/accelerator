# Как говорить с GigaChat

Памятка по официальной документации Сбера (прочитано 2026-10-15) и урокам проекта.
Источники: [Основы промпт-инжиниринга](https://developers.sber.ru/docs/ru/gigachat/prompts-hub/prompt-engineering),
[Генерация структурированных данных](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).

## Что советует Сбер

1. **Системный промпт из четырёх частей:** роль («Ты — …»), какие входные данные придут в запросе
   пользователя, задача, формат ответа и ограничения («Верни ТОЛЬКО …»). Пользовательский промпт —
   сами данные.
2. **Однозначность.** Противоречивые требования в одном промпте ломают ответ.
3. **Примеры** помогают, модель ищет в них закономерности. Количество подбирать опытом.
4. **Параметры:** `temperature` (меньше — предсказуемее, больше — разнообразнее) и `top_p` —
   альтернативы, **вместе их задавать не рекомендуется**. `repetition_penalty`: 1.0 — нейтрально,
   больше 1 — модель избегает повторов. `max_tokens` ограничивает длину.
5. **Структурированный вывод:** `response_format = {"type": "json_schema", "schema": …, "strict": true}`,
   все поля в `required`, у полей `description`. Без `required` модель вернёт произвольный JSON.
6. Модели обновляются: промпты нужно перепроверять на новых версиях.
7. Против выдумок: ограничить свободу интерпретации, давать проверяемые данные (источники), проверять факты.

## Что применено в проекте

- Чат Бруно (`gigachat.CHAT_SAMPLING`): `temperature 0.7`, `repetition_penalty 1.1`, `top_p` убран.
- Строгие схемы с `description` у полей: Мастерская идей (`ideas.schema_of`), анализ рынка
  (`market.MARKET_DESCRIPTIONS`). Остальные схемы (радар, разбор, акулы) не трогали, чтобы не менять
  поведение Бруно без отдельного прогона.
- Сырые идеи Мастерской — без схемы и с `temperature 1.0`; разбор — по схеме с `temperature 0.4`.

## Уроки проекта (дополняют документацию)

- Примеры тона GigaChat копирует дословно: примеры брать из другой предметной области и помечать
  «пример манеры, не факт».
- Даже со схемой модель иногда отвечает строками «ключ: значение» — разбор должен быть терпимым
  (`model_json.load_model_json`, `ideas.load_fields`).
- Поля в конце большой схемы модель пропускает: важное выносить в отдельный короткий запрос
  (`ideas.check_traps`).
- Числа модель выдумывает: всё, что не из источников и слов основателя, вырезает Python
  (`market._grounded`), деньги считает `economics.py`.
- Личный ключ даёт 429 на параллельные запросы: запросы к GigaChat идут по одному.
