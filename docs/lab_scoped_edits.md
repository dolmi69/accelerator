# Частичные доработки лаборатории

Первое создание сайта и явно выбранная полная пересборка используют генерацию
полного приложения. Остальные запросы к существующим сайтам — частичные правки.
Включённый LAB_RAW_AI_TEST_MODE больше не заставляет пересоздавать их целиком.

## Серверные приложения

1. Тот же анализ намерения, который определяет действие и сложность, возвращает
   `edit_files`: минимальный список файлов для текущей задачи. Все имена файлов
   и сбалансированные выдержки доступны анализатору, даже при большом app.py.
2. Если план отсутствует у старого клиента, отдельный анализ на Luna определяет
   файлы; код выполняется выбранной ранее моделью. Ошибка анализа не запускает
   полную сборку. Файлы не передаются как разрешение на исполнение кода в Django.
3. `backend_edits.py` запрашивает только точные замены в разрешённых файлах.
   Для каждой замены старый фрагмент должен встречаться ровно один раз.
   Новые assets или новый app.py при переходе со статического сайта создаются
   явно. Удаление разрешено только для выбранных необязательных файлов.
4. Все операции сначала применяются к копии словаря файлов. Проверяются пути,
   синтаксис app.py, обязательные файлы, HTML и локальные подключения assets.
   Только готовый валидный комплект сохраняется отдельной версией.
5. Не выбранные файлы остаются побайтно прежними. Модель не может расширить
   список сама. При ошибке/фильтрации предыдущая версия сохраняется; автоматического
   перехода на полную сборку нет. Завершённый некорректный ответ исправляется
   в ограниченном цикле, описанном ниже.

`checks.edit_plan` в отчёте содержит planned_files, changed_files, scope и policy.
Пользователь видит короткое пояснение: только оформление / клиент / сервер / оба
слоя. `edit_method=patch`. Исходная версия неизменна, публикация BrunoHost обновляется
только отдельным действием владельца. База не передаётся генератору.

## HTML-прототипы

Используется существующий механизм фрагментов и точных замен site_patches.py,
включая сырой режим. Результат не заменяет весь документ новым ответом модели.
Первый HTML и явно запрошенная пересборка остаются полноформатной генерацией.

## Особые случаи

Однозначное переименование выполняется локально через site_names.py без AI.
Изменения API с клиентом должны включать оба слоя в план; внутреннее исправление
сервера сохраняет клиентский контракт. Выбор модели и выбор файлов независимы:
дорогая модель не получает права переписывать не выбранные файлы.

Границы контролируются по файлам/точным фрагментам; смысловую правильность кода
и совместимость API всё равно нужно проверять в запущенном прототипе. Полный
анализ пользовательской бизнес-логики автоматическими проверками не заявляется.

Проверки: founder.test_backend_edits, founder.test_lab_intent,
founder.test_lab_raw, founder.test_generated_backend, founder.test_lab_costs.
Тесты выполняются с подставными ответами моделей и не расходуют API-токены.

## Автоматическое исправление неудачной правки

С 28.10.2026 локально отклонённый завершённый ответ не заканчивает задачу сразу.
Для доработки доступны максимум три попытки кода (LAB_EDIT_REPAIR_ATTEMPTS, 1–3):
первая точная правка, исправленная правка с конкретной ошибкой и затем полный код
только выбранных файлов. Область по-прежнему проверяется; весь проект автоматически
не пересоздаётся. При ошибке выбора файлов независимый анализатор Luna может
пересмотреть список по исходной задаче. Генератор не расширяет область сам.
Если отсутствует/ошибочен исходный план, анализатор делает до двух попыток плана.

HTML-прототипы получают до трёх корректирующих попыток точечных замен, включая
локальные проверки контракта. Каждая попытка применяется к исходной версии,
поэтому неуспех не оставляет промежуточный результат. Генерация кода сохраняет
выбранную модель: исправления не повышаются с Luna на Sol автоматически.

Все завершённые попытки и пересмотры плана входят в токены/request_ids итоговой
версии; непригодные ответы помечаются output_error. Отчёт содержит recovery с
числом попыток кода и всех вызовов. Лимиты бюджета по-прежнему проверяются каждым
вызовом. Частичные/отфильтрованные ответы не используются и не пересылаются модели;
ошибки провайдера с неизвестным списанием и отказы по секретам не повторяются.

При исчерпании попыток или недоступности провайдера сохранить рабочую правку
невозможно гарантировать. Старый сайт остаётся рабочим, задача явно помечается
неуспешной и в чате сохраняется конкретная причина и следующий шаг. Успех без
реального изменённого и проверенного комплекта файлов не показывается.

Эта политика заменяет прежний запрет на любые автоматические платные повторы
именно для завершённых ответов, не прошедших локальные проверки доработки.
Проверки восстановления: founder.test_lab_recovery.
