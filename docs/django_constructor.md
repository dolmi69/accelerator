# Конструктор Django: библиотека готовых модулей

Лаборатория сохраняет статический HTML или самостоятельное Django-приложение.
Готовый Python находится в `founder/blueprints/django_basic`. Qwen создаёт/правит
только главную страницу; модели, миграции, права и маршруты модели не генерируют.

## Использование

В лаборатории откройте «Разработка прототипа» → «Встроенные инструменты» →
«Возможности сайта», выберите модули и сохраните. Цвета, шрифт, название и форму
кнопок меняйте через обычное поле запроса; отдельного блока оформления нет. Тип сайта наследуется
от выбранной версии, блок для правки определяется автоматически.
Создаётся отдельная версия без AI. В локальной лаборатории рабочий сайт
автоматически запускается в предпросмотре через защищённый POST.
Кнопка «На весь экран» разворачивает тот же iframe поверх лаборатории в той же
вкладке: страница, заполненные поля и соединения не пересоздаются. Крестик, кнопка возврата,
Esc (в том числе внутри сайта) закрывают просмотр;
выбранная версия, введённый запрос и прокрутка лаборатории сохраняются.
Закрытие полного экрана не останавливает сервер. У одного пользователя работает
только один локальный прототип: при переходе в другой свой проект предыдущий
сервер автоматически останавливается. База, аккаунты, переписки и файлы сохраняются.
Переключение выполняется защищённым POST, в том числе при открытии карточки или
радара другого проекта. Старый предпросмотр в другой вкладке закрывается; его
можно открыть снова кнопкой, остановив текущий прототип. Запоздавший запрос из
прошлого проекта не может запустить его повторно после переключения.
В отдельно открытом локальном сайте
также есть кнопка «Вернуться в лабораторию». Макет без бэкенда можно развернуть
кнопкой под предпросмотром.
Для создания владельца — отдельного аккаунта сайта — используйте «Настроить
аккаунт владельца» в разделе «О версии». Обычный предпросмотр открывает главную
страницу, не одноразовую ссылку настройки. «Остановить» возвращает в лабораторию
с отключённым автозапуском; сайт можно снова запустить кнопкой в предпросмотре.
Через «Кабинет» можно добавлять карточки, смотреть заявки, заказы и записи;
через «Команда и права» — приглашать зарегистрированных участников и назначать
сотрудников. В профиле доступны логин, имя, описание, email и аватарка.

По умолчанию отмечена только регистрация. Сброс пароля, чаты, уведомления
и остальные функции подключаются по выбору. Вход владельца, профиль
и управление ролями сохраняются. «Основы маркетплейса» — каталог/поиск,
заявки, файлы и публикации. Остальные группы — работа с клиентами и продажи.
Зависимости (например, каталог для избранного) устанавливаются автоматически.

Галочки отправляются и при AI-генерации дизайна. Кнопка «Создать готовую основу — 0 токенов» подключает модули без AI; индивидуальный дизайн оплачивается отдельно по расходу токенов. Если ответ AI оборвался, для Django сохраняется готовая основа с выбранными модулями без автоматического повторного AI-запроса.

Готовая основа помечена в интерфейсе как версия без индивидуального дизайна.
Первый AI-дизайн такой основы создаётся целиком, а не короткими правками
запасного HTML; последующие изменения готового дизайна используют патчи.
Первый дизайн получает до 16 384 выходных токенов и до 300 секунд ожидания;
точечные доработки — до 2048 токенов (значения по умолчанию, локальная конфигурация
может их повышать). Qwen получает текущий HTML целиком и возвращает точные замены.
Пользователь не выбирает область. Отдельного запроса для выбора участков нет.
Увеличение лимита даёт место для деталей и завершения HTML, но не означает
обязательную трату всех токенов. Денежные ограничения продолжают действовать.
Модель получает компактные данные проекта: название, описание, аудиторию,
решение, выбранные модули и настройки оформления. Инструкция задаёт визуальное
направление, композицию, типографику и адаптивность. Это не гарантия качества
каждого ответа: ограничения длины и отсутствие внешних фото/шрифтов сохраняются.

Поле `LabSiteVersion.backend_modules` сохраняет набор для каждой версии;
экспортируемый `site.json` содержит нормализованный список. Правки оформления
и HTML наследуют набор. Отключение не удаляет таблицы или данные, но закрывает
маршруты и убирает интерфейс. Новая версия использует прежнюю DB,
файлы, секрет и имена cookies.

## Расход токенов

Выбор модулей и следующие команды выполняются локально:

- «добавь регистрацию и сброс пароля»;
- «добавь каталог и избранное»;
- «подключи заявки и бронирование»;
- «добавь корзину и заказы».

Диспетчер `services/backend_modules.py` распознаёт ограниченные команды
из списка. Смешанные/неизвестные требования (Google login, оплата в долларах,
изменения цвета одновременно с модулем) не считаются полностью выполненными
шаблоном и продолжают обычный путь редактора. Новая нейронка для классификации
не подключена. По повторной отправке сохранённая настройка переиспользуется.
Нулевые токены установки не означают бесплатный хостинг, почту или платёжный сервис.

## Границы и проверки

- Формы и данные модулей обрабатываются доверенным Django-кодом. Их навигация визуально встроена в AI-страницу; переходы проверяются родительским окном по iframe и точному списку разрешённых маршрутов. AI HTML остаётся в sandbox.
- Встраивание локального бэкенда разрешено через CSP только из явно указанного
  локального адреса лаборатории. Контекст `.lab-viewer.json` не экспортируется;
  в публичном режиме интерфейс возврата отключён. Сообщение о закрытии проверяется
  по отправившему iframe и origin; AI макет остаётся в sandbox с непрозрачным origin.
- Владелец подтверждается одноразовой ссылкой; публичная регистрация не даёт прав.
  Приглашение закреплено за конкретным аккаунтом, ограничено сроком и одноразовое.
- Заявки/переписки/заказы не показываются другим участникам. Владелец и сотрудники
  управляют бизнес-данными сайта. Роли проверяются сервером.
- Галерея доступна вместе с опубликованной карточкой, остальные файлы скачиваются
  только через проверку доступа. Максимальный размер файла 5 МБ.
- Бронирование и заказ транзакционные; цена вычисляется сервером,
  повтор заказа идемпотентный, отмена возвращает остатки один раз.
- Платёжная интеграция выключена без собственных ключей. Webhook не доверяет
  присланному статусу, подтверждение проверяется через API ЮKassa. Проверена
  тестами с ответами-заготовками; живой магазин не подключался.
- Почта по умолчанию локальная (журнал), для доставки нужен SMTP своего сайта.
- Отдельный процесс не наследует API-ключи и DB ускорителя. ZIP содержит только
  исходники и `.env.example`, без пользователей, файлов, `.env` и локальных секретов.

Файлы запуска: `.runtime/lab-backends/<startup UUID>/project/`;
журнал: `.runtime/lab-backends/<startup UUID>/server.log`.
Локальный запуск доступен только с Mac/Linux на loopback: один активный проект
на аккаунт, до трёх процессов разных пользователей. Переключение проекта закрывает предыдущий.
Публичная карточка ускорителя показывает sandbox главной страницы; это не
облачный хостинг нового бэкенда. Для нескольких ASGI workers нужен Redis.

Проверки ускорителя: `python manage.py test founder.test_django_builder founder.test_lab founder.test_lab_costs`.
Проверки скачанного проекта: `python manage.py test core`.

### Замена надписей без AI

Команда `замени регистрацию на registration` меняет видимую надпись в готовых Django-шаблонах и в HTML прототипа, создавая отдельную версию без AI-токенов. Также работает точная замена другого текста: `замени "Войти" на "Sign in"`. Замены сохраняются в `presentation.text_replacements`, входят в ZIP и применяются при запуске выбранной версии. Маршруты и обработчики остаются прежними; если текст не найден, лаборатория показывает ошибку вместо фиктивного успеха.

### Распознавание готовых правок

Понятные команды вроде `измени шрифт на классический` применяются локально
за 0 AI-токенов. Остальные задания в кузнице сразу получает Qwen: один ответ
содержит либо готовые настройки/модули, либо точечные правки кода, вместе с отчётом.
Нет промежуточных запросов GigaChat и отдельного платного классификатора.
Свободное распознавание Qwen всё равно использует токены. Нестандартная часть
смешанного запроса не должна теряться ради шаблона. Кеш повторного запроса,
локальные команды, границы секретов и учёт затрат сохранены.

### Общая тема и встроенная навигация

На главной нет второй внешней шапки: настоящие кнопки модулей вставляются в `data-app-navigation` внутри сгенерированной страницы. В старых сайтах — в существующую шапку, main или основной контейнер. Нейронка получает инструкцию оставлять этот контейнер при создании и правках.

Цвет кнопок, фон, поверхность карточек, текст, шрифт и скругления извлекаются локально из CSS сайта и применяются к регистрации, профилю, чатам и другим страницам. Это не требует AI-токенов и входит в скачиваемый Django-проект. Неизвестные значения получают безопасные стандартные значения; произвольные CSS-выражения не исполняются.

Переход из sandbox идёт через проверяемое сообщение родителю; ни cookies, ни доступ к DOM родителя не выдаются сгенерированному коду. Высота страницы синхронизируется, чтобы не было второго фиксированного окна прокрутки. Формы макета получают только локальный JS submit-event, сетевые отправки остаются запрещены.

### Ответ Бруно рядом с прототипом

После запроса лаборатория показывает Бруно под предпросмотром с кратким отчётом. Для AI-правок Qwen возвращает конкретный результат и ограничения, Бруно показывает этот отчёт, а сервер бесплатно проверяет допустимые инструменты и интерфейс серверных действий. Отдельной AI-проверки больше нет. Проверка исходного кода не обозначается как выполненный браузерный тест или доставка сообщения. Для локальных правок отчёт строится сравнением версий без AI. Неизвестный расход не обозначается как нулевой. Повтор готового запроса, отсутствие изменений и незавершённый дизайн получают отдельные сообщения. Пока запрос выполняется, старый отчёт скрывается, а внутри предпросмотра работает анимация кузницы.

Плашка исчезает после 60 секунд видимости в окне браузера. За пределами экрана, в неактивной вкладке и при полноэкранном просмотре отсчёт приостанавливается. Перезагрузка страницы в той же вкладке не начинает отсчёт заново. Для каждой новой версии снимок отчёта сохраняется в `LabSiteVersion.bruno_report` вместе с запросом; в «Истории» его можно раскрыть без ограничения по времени. Старые версии получают отчёт из уже сохранённых данных. Сообщение о повторном открытии из кеша не меняет исходный расход в истории.

### Настоящее сохранение и отправка расчётов

В запущенном Django-сайте изолированная главная страница получает готовый `window.BrunoApp`:

- `await BrunoApp.auth.getSession()` — настоящий текущий аккаунт и подключённые возможности; `BrunoApp.auth.login()` — переход ко входу.
- `await BrunoApp.results.save({title, content})` — подтверждение сохранения текста в приватные «Мои результаты».
- `await BrunoApp.results.list()` — сохранённые результаты текущего пользователя.
- `await BrunoApp.chat.shareResult({title, content})` либо `{resultId}` — выбор получателя и подтверждение. Результат сохраняется в аккаунте, сообщение — в обычном Django-чате. Нужен модуль `chat`.

Название ограничено 120, текст — 1800 символами. В ответе записи `persisted:true` появляется только после сохранения сервером. При отмене, выходе из аккаунта, отключённом модуле или ошибке нельзя показывать фиктивный успех. Само сохранение/отправка не вызывает AI. Добавление нестандартной кнопки через свободный запрос использует AI-разбор и правку кода.

Сгенерированный HTML остаётся в opaque sandbox без cookies, доступа к родителю и сетевых запросов. Действия выполняет доверенная оболочка: фиксированные маршруты, CSRF, проверка настоящей сессии, владения результатом и выбранного получателя. Выбор и подтверждение выполняются вне сгенерированной страницы; чужой результат нельзя прочитать или отправить. Повтор отправки с тем же nonce не создаёт копию сообщения. HTTP и WebSocket используют одну запись сообщений; получатель получает обновление через канал своего чата, а сохранённая история остаётся после перезагрузки.

Проверка Бруно отклоняет `authModule`/`chatModule` заглушки, неизвестные методы BrunoApp, отправку без `chat`, отсутствие настоящего вызова по запросу сохранения/отправки и отсутствие ожидания серверного ответа. Это ограниченная проверка исходного кода, а не доказательство правильности произвольного JavaScript. Дополнительно выполнены тесты серверных действий, WebSocket-доставки, оболочки и браузерный сценарий двух тестовых аккаунтов. Публичный статический sandbox карточки не заменяет запущенный Django-сервер.

### Собственные компоненты готовых страниц

Регистрация/вход, пароль, профиль, каталог, товар, корзина, заказы, бронирования,
команда, публикации, уведомления, сообщения и результаты используют нашу HTML/CSS
верстку в blueprint. Django продолжает проверять формы и сохранять данные;
`form.as_p` заменён явными полями с привязанными подписями, подсказками и ошибками.
Пароль можно показать; файл/аватар получает локальное название/предпросмотр.
Функции работают без этих JS-улучшений. Все новые компоненты наследуют цвета и
шрифт прототипа, поддерживают телефон и клавиатуру, входят в ZIP и локальный запуск.

Кабинет сгруппирован в раскрываемые разделы, каталог показывает реальные
загруженные изображения и сохраняет фильтры, корзина имеет отдельное удаление,
список переписок показывает последний текст без доступа к чужим чатам.
Перезапуск прежней версии подхватывает новые файлы blueprint по fingerprint;
её база данных, аккаунты, заказы и переписки сохраняются.
