# Qwen для создания сайтов через Cloud.ru

Генератор подключается отдельно от Бруно. Текущие чат, радар, карточки и задания
продолжают использовать `AI_PROVIDER=gigachat`. Менять его для генератора не нужно.

## Настройка

1. Войти в [кабинет Cloud.ru](https://console.cloud.ru/).
2. Проверить наличие Foundation Models и доступ к `Qwen/Qwen3-Coder-Next`.
3. Создать сервисный аккаунт проекта и API-ключ для Foundation Models по
   [официальной инструкции](https://cloud.ru/docs/foundation-models/ug/topics/quickstart).
4. Сохранить **Key Secret** в локальном `.env`. Файл исключён из Git.

```dotenv
AI_PROVIDER=gigachat
CLOUDRU_API_KEY=
QWEN_CODE_MODEL=Qwen/Qwen3-Coder-Next
QWEN_CODE_MAX_TOKENS=8192
QWEN_CODE_TIMEOUT=180
```

Ключ OpenAI или OAuth-ключ прямого GigaChat сюда не подходит. После изменения
настроек уже работающий сервер нужно перезапустить. Веб-клиент ключ не получает.
Пополнять баланс следует только после проверки кабинета и тарифа модели.
Адаптер не может достоверно определить баланс из произвольной ошибки API.

## Проверка подключения и пробная генерация

Команды выполняются из каталога Django-проекта. Проверка отправляет один
небольшой платный запрос с максимум 16 выходными токенами:

```sh
.venv/bin/python manage.py check_qwen
.venv/bin/python manage.py qwen_site --prompt 'Сделай небольшой сайт о здоровом сне с тремя советами и кнопкой раскрытия подробностей' --max-tokens 4096
```

Результат сохраняется в новом каталоге `.runtime/qwen-sites/<uuid>/`:
`index.html` и `usage.json`. Путь печатается в терминале. Для изменения:

```sh
.venv/bin/python manage.py qwen_site --input .runtime/qwen-sites/<uuid>/index.html --prompt 'Добавь тёмную тему'
```

Результат правки сохраняется отдельно, исходный файл не перезаписывается.
Сервис для будущего интерфейса: `founder.services.site_generator.generate_site`.
Он возвращает HTML, ID модели и реальные счётчики токенов из ответа API.

## Границы этой интеграции

- Один вызов на генерацию; автоматических повторов и смены провайдера нет.
- Лимит ответа и время ожидания заданы отдельно от чата. При обрезанном ответе
  неполный сайт не сохраняется. Тайм-аут не гарантирует отмены оплаты провайдером.
- Ошибки ключа, доступа, модели, оплаты, квоты и сети преобразуются в сообщения
  без ключей, исходного кода и сырого ответа провайдера в логах.
- `usage.json` содержит расход успешной генерации. Это ещё не денежный баланс
  пользователя: неудачные запросы тоже могут быть оплачены; их нужно учитывать
  отдельно при разработке платежей и очереди заданий.
- Сгенерированный HTML — недоверенный код. Проверка целостности документа
  не является антивирусом или очисткой JavaScript. Код не исполняется на сервере
  и не публикуется под доменом приложения.
- Экран лаборатории, изолированный предпросмотр, публикация, права доступа,
  пользовательские квоты генератора и платежи — следующий этап. Текущий вход
  в генератор доступен разработчику через команду, публичного endpoint нет.

Модель и адрес API сверены 6 октября 2026 года по
[каталогу Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models)
и [быстрому старту](https://cloud.ru/docs/foundation-models/ug/topics/quickstart).
Статус реального подключения подтверждает только успешный `check_qwen` с ключом.

## Проверено при подключении 6 октября

115 тестов проекта прошли, в том числе 9 новых проверок генератора. В кабинете
создан отдельный сервисный аккаунт `bruno-site-builder` уровня проекта без
административных ролей. Пользователь выпустил API-ключ для Foundation Models
на 90 дней; секрет сохранён только в локальном `.env`.

Первый настоящий `check_qwen` получил HTTP 402. После пополнения пользователем
проверка прошла: `Qwen/Qwen3-Coder-Next`, 23 входных и 2 выходных токена.

Проверена настоящая генерация и правка простого сайта «Тихое утро»:

- Первый запрос страницы превысил прежний тайм-аут 90 секунд. Время ожидания
  увеличено до 180 секунд; повтор выполнен вручную с более компактным заданием.
- Генерация полного HTML: 431 входной и 833 выходных токена. В JavaScript
  обнаружена ошибка: вызов `filter` у `NodeList`.
- Через `--input` исходная страница и описание ошибки переданы Qwen. Модель
  исправила её с помощью `Array.from`; расход правки — 1220 / 665 токенов.
  Ручных изменений в сгенерированный HTML не вносилось.
- Исправленная страница проверена в браузере на отдельном локальном порту
  с CSP sandbox: три галочки дают 3/3, сброс возвращает 0/3 и снимает галочки,
  повторный выбор двух пунктов даёт 2/3. Ошибок в консоли не обнаружено.
- После изменения тайм-аута 9 тестов интеграции повторно прошли.

Артефакты и снимок проверки находятся в игнорируемом каталоге
`.runtime/qwen-sites/e2677d9c-3f0d-41d5-85c4-3f64e8ca15e0/`.
Локальная страница — разовая проверка интеграции, а не готовый экран лаборатории.
Успешный пример не гарантирует корректность следующих генераций: перед выпуском
нужны проверки JavaScript, изоляция и ограниченный цикл исправлений. Полный расход
с учётом запроса, завершившегося тайм-аутом, нужно смотреть у провайдера.
