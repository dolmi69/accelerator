# Qwen для создания сайтов через Cloud.ru

Генератор подключается отдельно от Бруно. Текущие чат, радар, карточки и задания
продолжают использовать `AI_PROVIDER=gigachat`. Менять его для генератора не нужно.

## Настройка

1. Войти в [кабинет Cloud.ru](https://console.cloud.ru/).
2. Проверить наличие Foundation Models и доступ к `Qwen/Qwen3-Coder-Next`.
3. Создать сервисный аккаунт проекта и API-ключ для Foundation Models по
   [официальной инструкции](https://cloud.ru/docs/foundation-models/ug/topics/quickstart).
4. Сохранить **Key Secret** в локальном `.env`. Файл исключён из Git.

```dotenv
AI_PROVIDER=gigachat
CLOUDRU_API_KEY=
QWEN_CODE_MODEL=Qwen/Qwen3-Coder-Next
QWEN_CODE_MAX_TOKENS=16384
QWEN_CODE_TIMEOUT=300
LAB_CREATE_MAX_TOKENS=16384
LAB_PATCH_MAX_TOKENS=2048
LAB_CREATE_TEMPERATURE=0.6
LAB_PATCH_TEMPERATURE=0.2
LAB_REQUESTS_PER_DAY=10
LAB_GLOBAL_REQUESTS_PER_DAY=30
```

Ключ OpenAI или OAuth-ключ прямого GigaChat сюда не подходит. После изменения
настроек уже работающий сервер нужно перезапустить. Веб-клиент ключ не получает.
Пополнять баланс следует только после проверки кабинета и тарифа модели.
Адаптер не может достоверно определить баланс из произвольной ошибки API.

## Временный тестовый режим: лимиты ×5

С 10.10.2026 на локальном Mac по просьбе владельца действуют увеличенные
значения в `.env`. Значения по умолчанию и `.env.example` сохраняют обычный
профиль; перед публичным запуском нужно отдельно выбрать рабочие бюджеты.

```dotenv
QWEN_CODE_MAX_TOKENS=81920
LAB_CREATE_MAX_TOKENS=81920
LAB_PATCH_MAX_TOKENS=10240
QWEN_CODE_TIMEOUT=1500
QWEN_INPUT_BYTE_LIMIT=160000
LAB_PATCH_MAX_RESPONSE_CHARS=120000
LAB_PATCH_MAX_FIND_CHARS=30000
LAB_PATCH_MAX_REPLACEMENT_CHARS=60000
LAB_MAX_REQUEST_RUB=50
LAB_USER_DAILY_RUB=100
LAB_USER_MONTHLY_RUB=500
LAB_GLOBAL_DAILY_RUB=1000
LAB_GLOBAL_MONTHLY_RUB=10000
LAB_GLOBAL_REQUESTS_PER_DAY=150
AI_REQUESTS_PER_MINUTE=60
AI_REQUESTS_PER_DAY=1000
LAB_REQUESTS_PER_DAY=0
```

Последний персональный счётчик обращений уже был отключён для разработки;
`0` оставлен без изменения. Денежные лимиты учитывают все попытки, включая
ошибки. 50 ₽ — резерв на отдельный вызов API, а не цена или общий предел
целого пользовательского действия. Оплачивается фактический расход.

Вместе с токенами подняты ограничения размера JSON-патча и заменяемого текста:
большой завершённый ответ не должен отбрасываться старым пределом в символах.
Блокировка параллельных запросов действует на всё время обработки, включая
локальную проверку результата, и снимается после завершения.

Каталог [Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models)
и API `/v1/models` указывают контекст Coder-Next 262 144 токена. Короткий
реальный вызов 10.10.2026 с `max_tokens=81920` принят провайдером; ответ
использовал только 2 выходных токена. Это проверка параметра, а не гарантия
завершения любого сайта за отведённое время.

## Первый дизайн и доработки

Первый индивидуальный дизайн, включая дизайн бесплатной Django-основы,
получает до 16 384 выходных токенов и тайм-аут 300 секунд. Верхний предел
адаптера увеличен тоже: иначе он обрезал бы новый лимит генератора. Инструкция
задаёт художественное направление под нишу, выразительный первый экран,
предметную SVG/CSS-графику, адаптивную композицию и работающие действия.
Максимум токенов — запас для завершения, не обязательный размер ответа.
Больший лимит и температура 0.6 не меняют модель и не гарантируют качество.

Последующие AI-правки возвращают точные JSON-замены, а не весь новый документ.
Фактические лимиты берутся из настроек/.env (тестовые значения выше обычных).
Кузница использует **один запрос Qwen**: пользовательское задание, текущий HTML,
компактные факты прототипа и список готовых модулей. Модель либо возвращает
настройки шаблона, либо код, вместе с отчётом и нужными стандартными модулями.
Отдельного классификатора, GigaChat-плана, GigaChat-проверки и Qwen-планировщика
областей нет. Для больших сайтов передаётся полный текущий HTML: это увеличивает
вход отдельной правки по сравнению с прежним выбором фрагментов, зато устраняет
второй вызов и сохраняет контекст зависимостей. Выход остаётся точечным патчем.

Галочки, распознанные локальные команды и повтор сохранённого запроса остаются
без AI. Свободный запрос, который распознал Qwen, оплачивает его вход/выход,
даже когда выбран готовый инструмент. «Без генерации кода» не означает «0 токенов».
Денежные резервации, фактический учёт и запрет автоматических платных повторов
сохранены. Локальные проверки выполняются без вызова модели.

Проверка распознавания 9 октября: настоящий запрос `измени шрифт` в лаборатории
GreenShelf распознан как готовый классический шрифт. Код Qwen не генерировал:
623 входных и 17 выходных токенов, учтено 0,080154 ₽ по настроенному тарифу.
В рабочем предпросмотре проверен применённый `Georgia, serif`; сохранена новая версия.

Результаты с `alert()` получают локальную обратную связь внутри страницы:
нативное окно браузера блокируется sandbox. Пустые ссылки `href="#"`
перехватываются для предотвращения ошибки селектора в типичном коде модели.
Это не подключает новые бизнес-функции и не снимает ограничения sandbox.

Проверка 8 октября: один запрос для `maison de perfum` с пределом 16 384
завершился полным HTML; API сообщил 1364 входных и 10 298 выходных токенов.
Учтённый расход — 2,67912 ₽ по настроенному тарифу. Исходный результат сохранён
отдельно; проверенная версия исправляет сообщения, помечает цены как примеры
и убирает выдуманный адрес без повторного AI-запроса. В браузере проверены
переход к коллекции, сообщения карточек и мобильная ширина 390 px. Для будущих
генераций инструкции требуют явной маркировки примерных данных. Это инструкция
модели, а не гарантия фактической точности каждого следующего результата.

## Проверка подключения и пробная генерация

Команды выполняются из каталога Django-проекта. Проверка отправляет один
небольшой платный запрос с максимум 16 выходными токенами:

```sh
.venv/bin/python manage.py check_qwen
.venv/bin/python manage.py qwen_site --prompt 'Сделай небольшой сайт о здоровом сне с тремя советами и кнопкой раскрытия подробностей' --max-tokens 4096
```

Результат сохраняется в новом каталоге `.runtime/qwen-sites/<uuid>/`:
`index.html` и `usage.json`. Путь печатается в терминале. Для изменения:

```sh
.venv/bin/python manage.py qwen_site --input .runtime/qwen-sites/<uuid>/index.html --prompt 'Добавь тёмную тему'
```

Результат правки сохраняется отдельно, исходный файл не перезаписывается.
Веб-лаборатория использует тот же сервис: `founder.services.site_generator.generate_site`.
Он возвращает HTML, ID модели и реальные счётчики токенов из ответа API.

## Лаборатория в проекте

Войдите в Co-Founder.AI, откройте проект и вкладку «Лаборатория сайтов».
Свободный запрос в кузнице сразу получает Qwen. Его ответ содержит правку или
готовую настройку, выбранные модули и конкретный отчёт. Сервер проверяет формат,
допустимые инструменты, секреты и контракты готовых действий. Это проверка кодом,
а не второе мнение нейросети и не браузерное выполнение JavaScript. После её
успеха создаётся новая приватная версия. Бруно показывает сохранённый отчёт Qwen
под прототипом; можно открыть старую версию или создать новый сайт.

Предпросмотр показан внутри страницы в `iframe sandbox="allow-scripts"`.
Ответ самого предпросмотра дополнительно получает CSP `sandbox allow-scripts`
с запретом сетевых запросов, внешних ресурсов, вложенных страниц и отправки форм.
Оба ограничения создают изолированное происхождение для HTML, даже если он
содержит JavaScript. На генерацию действует общий лимит запросов к ИИ и отдельный
лимит 10 обращений в сутки на аккаунт и 30 для всего сервиса по умолчанию.
Фактические токены успешной
генерации сохраняются с версией.

## Границы этой интеграции

- Кузница вызывает только Qwen. Обычные чат, радар и задания Бруно сохраняют
  свою существующую настройку GigaChat. Старые `LAB_BRUNO_*` параметры относятся
  к прежнему координатору и в текущем маршруте генерации не используются.
- Расход каждого запроса Qwen фиксируется в `LabAIUsage`. При тайм-ауте резерв
  остаётся учтённым: точный расход неизвестен. Платных повторов автоматически нет.
- Текущий прототип важнее анкеты; инструкция требует сохранять назначение и формулы.
  Локальная проверка отдельно отклоняет известную ошибку «калории → смета» и
  нарушения интерфейса готовых серверных действий. Она не гарантирует отсутствие
  всех смысловых ошибок или правильность произвольного JavaScript.
- Серверные AI/API-интеграции пока отсутствуют. Запросы на использование ключей
  Co-Founder.AI, чтение .env или подключение настоящего AI отклоняются
  с объяснением; макет чата возможен только при явной просьбе о демонстрации.
- Отчёт Qwen объясняет конкретные изменения и невыполненные части.
  Отчёт сохраняется с версией в истории; для старых версий остаётся прежний отчёт.
- Лимит ответа и время ожидания заданы отдельно от чата. При обрезанном ответе
  неполный сайт не сохраняется. Тайм-аут не гарантирует отмены оплаты провайдером.
- Ошибки ключа, доступа, модели, оплаты, квоты и сети преобразуются в сообщения
  без ключей, исходного кода и сырого ответа провайдера в логах.
- `usage.json` содержит расход успешной генерации. Это ещё не денежный баланс
  пользователя: неудачные запросы тоже могут быть оплачены; их нужно учитывать
  отдельно при разработке платежей и очереди заданий.
- Сгенерированный HTML — недоверенный код. Проверка целостности документа
  не является проверкой работоспособности JavaScript. Код не исполняется на сервере.
- Текущие возможности конструктора, скачивание, локальный запуск и границы
  встроенных модулей описаны в [django_constructor.md](django_constructor.md).
  Локальный запуск бэкенда не является облачным хостингом пользовательских сайтов.

Модель и адрес API сверены 6 октября 2026 года по
[каталогу Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models)
и [быстрому старту](https://cloud.ru/docs/foundation-models/ug/topics/quickstart).
Статус реального подключения подтверждает только успешный `check_qwen` с ключом.

## Наши правила дизайна и возможность обучения

`founder/design_guides/qwen_frontend.md` — редактируемый набор инструкций: сохранение продукта и формул, выразительная композиция,
система отступов, типографика, осмысленные SVG, адаптивность, понятные отчёты.
Он добавляется к первому дизайну/полной пересборке; на точечных правках не
отправляется повторно. Это контекст для модели, **не обучение её весов**.

[Документированный API Foundation Models](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs)
предоставляет `/models` и `/chat/completions`, без endpoint дообучения.
Поэтому через текущую интеграцию создать персональную обученную Qwen нельзя.
[Официальные инструменты Qwen](https://github.com/QwenLM/Qwen3-Coder/tree/main/finetuning)
предусматривают обучение открытых весов отдельно: нужен набор качественных
примеров и собственное GPU-окружение/развёртывание модели. Платное обучение или
новая инфраструктура в этом обновлении не запускались.

## Библиотека компонентов Forge — 11.10.2026

В `founder/design_guides/components/` находятся восемь групп примеров HTML,
общий CSS и JS для локальных фильтров и доступных вкладок. При первом дизайне
Qwen получает каталог, при правке — краткие правила и до трёх примеров по теме
запроса. Компоненты необязательны: модель выбирает композицию и может писать
свои блоки. Нет обязательной бежевой палитры или одинакового набора секций.

`site_components.py` встраивает ресурсы непосредственно в сохранённый HTML.
Предпросмотр, скачанный HTML и Django-экспорт используют одинаковые ресурсы.
Базовые стили находятся в отдельном слое каскада: собственный CSS сайта имеет
приоритет. При следующих AI-правках общий CSS/JS удаляется из контекста модели
и возвращается при сохранении; собственные стили, формулы и обработчики остаются.
Идентификаторы выбранных фрагментов сохраняются после удаления общих ресурсов.

Это не дообучение весов. Подключение ресурсов локальное; создание дизайна и
передача каталога всё ещё используют токены единственного вызова Qwen.
Точный расход зависит от объёма сайта и ответа, фиксированная экономия не обещается.
