# Локальный запуск на Windows

Поддерживаемый путь: Windows 10/11, Python 3.14, отдельное виртуальное окружение.
Node.js 22 или новее нужен для JS-тестов и сборки CSS; для запуска сайта он не обязателен.

## Первый запуск

1. Установите Python 3.14 с Python Launcher (`py`) и Git. Склонируйте проект.
2. В папке проекта откройте `setup.bat`: он создаст `.venv`, установит зависимости,
   создаст `.env` из примера, если файла ещё нет, и применит миграции.
3. Откройте `start.bat`. Сайт откроется по адресу `http://127.0.0.1:8000/`.
4. Для остановки нажмите Ctrl+C в окне запуска.

Существующие `.env` и база не перезаписываются. Окружение `.venv` с Mac не переносите:
на Windows оно создаётся заново. Папки с пробелами и кириллицей поддерживаются.
В примере включён `AI_PROVIDER=demo`; для настоящего AI нужны свои ключи.
`configure_ai.bat` настраивает GigaChat локально, без отправки ключа в чат.

Из PowerShell можно запустить напрямую, без активации окружения:

```powershell
.\.venv\Scripts\python.exe start_local.py
# Другой порт, если 8000 занят:
.\.venv\Scripts\python.exe start_local.py --port 8002
```

`start_local.py` одинаково используется на Mac, Linux и Windows: применяет миграции,
проверяет свободный порт и открывает браузер после готовности сервера.

## Лаборатория

Готовые Django-сайты запускаются из лаборатории также на Windows. У каждого своя база,
ключ Django и cookies. При смене проекта прежний сайт останавливается; данные сохраняются.
AI-ключи основного сервиса в дочерний процесс не передаются.

Блокировка использует `msvcrt` на Windows и `fcntl` на Mac/Linux. Для Windows остановка
ждёт завершения процесса через системный handle: `os.kill(pid, 0)` не используется.
См. [блокировки Python](https://docs.python.org/3.14/library/msvcrt.html#msvcrt.locking)
и [поведение os.kill на Windows](https://docs.python.org/3.14/library/os.html#os.kill).

## Проверка изменений

```powershell
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test founder
.\.venv\Scripts\python.exe manage.py test_blueprint
npm test
```

`test_blueprint` тестирует скачиваемый Django-проект во временной папке, с отдельной
базой и без API-ключей. Подготовлен workflow GitHub Actions для Ubuntu и Windows;
на 11 октября 2026 года результаты запуска на Windows ещё не получены.
Нативный тест лаборатории запускает настоящий сайт из папки с кириллицей и пробелами,
останавливает его и запускает снова. Файлы читаются и пишутся явно в UTF-8.

## Telegram и Redis

Для работы только на одном локальном сервере оставьте `REDIS_URL` пустым.
Для общего потока событий между сайтом и Telegram нужен доступный Redis, например
запущенный в Docker/WSL. Mac-бинарник `.tools/valkey-server` на Windows не запускается.
Недоступный Redis не заменяется незаметно другим каналом.

Для временного Telegram-туннеля нужен `cloudflared.exe` в `.tools/` или `cloudflared`
в PATH. Команда: `.\.venv\Scripts\python.exe start_telegram_local.py`.
Ключ бота задаётся локально в `.env`. Создание внешнего туннеля отдельно от запуска сайта.

## Дневной лимит и основа Pro

`LAB_REQUESTS_PER_DAY=10` — персональный лимит платных AI-генераций лаборатории за 24 часа.
`LAB_PRO_REQUESTS_PER_DAY=50` применяется при действующем `User.pro_until`.
Срок можно задать в админке; платная оплата и страница тарифов сюда не входят.
После истечения срока действует обычный лимит, уже использованные запросы не сбрасываются.
Готовые инструменты и попадания в кеш не расходуют этот лимит. Денежные и общие ограничения
по-прежнему действуют. `LAB_REQUESTS_PER_DAY=0` отключает персональную квоту для локальных
экспериментов; это не настройка публичного запуска.
