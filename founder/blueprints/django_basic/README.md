# Сайт из лаборатории Co-Founder.AI

Самостоятельное Django-приложение со своей базой и файлами. Готовые модули
перечислены в `site.json` → `modules`; зависимости добавляются автоматически.
Python-код модулей написан заранее. Нейронка создаёт только главную страницу.

## Запуск

1. Создайте виртуальное окружение: `python -m venv .venv`.
2. Активируйте его и установите `pip install -r requirements.txt`.
3. Запустите `python start_local.py --port 9000`.
4. При первом запуске откройте `http://localhost:9000/setup/<содержимое .owner-setup>/`.
   Создайте отдельный аккаунт владельца. Ссылка одноразовая, последующие регистрации
   создают обычных участников. Альтернатива: `python manage.py createsuperuser`.
5. Откройте «Кабинет», добавьте карточки и настройте свободное время. Для проверки
   заказов, записей и чатов создайте второй аккаунт в другом браузере.

Владелец управляет командой и админкой. Сотрудник обрабатывает содержимое,
заявки и заказы. Участник видит свои заявки, заказы, записи и переписки.
По умолчанию карточки создают владелец и сотрудники; разрешить участникам
создавать свои объявления можно в «Команда и права».

## Модули

Аккаунты, смена/сброс пароля, профиль с аватаркой, личные WebSocket-чаты,
уведомления и управление командой доступны согласно выбору в `site.json`. Дополнительные модули:

- `catalog`: карточки с описанием, категорией, ценой и остатком;
  поиск, фильтры, сортировка, страницы результатов, редактирование и черновики.
- `leads`: формы заявок, контакты и текст, статусы новая/в работе/закрыта.
- `uploads`: JPG/PNG/WebP, PDF/TXT. Картинки переведены в JPEG; галерея опубликованной
  карточки общедоступна, документы доступны автору и сотрудникам как скачивания.
- `favorites`: личный список сохранённых карточек.
- `booking`: свободные интервалы, бронирование и отмена. Время автора не пересекается,
  один интервал не может быть забронирован одновременно дважды.
- `orders`: корзина, заказ, текущие цены на сервере, остатки, статусы и отмена.
  Один заказ относится к одному продавцу. Повтор отправки не создаёт второй заказ.
- `reviews`: отзывы 1–5, проверка автором/сотрудником; изменение требует новой проверки.
- `pages`: текстовые страницы/публикации, черновики и публикация, без исполнения HTML.
- `payments`: опциональная интеграция редирект-оплаты ЮKassa.

Данные: `db.sqlite3`, файлы: `uploads/`. При обновлении сохраняйте
базу, папку файлов, `.env` и `.local-secret`, затем запускайте миграции.
Отключение модуля скрывает интерфейс и блокирует маршруты, данные не удаляет.

## Письма и оплата

Скопируйте `.env.example` в `.env` и задайте собственные параметры сайта.
Для почты нужен SMTP. В локальном режиме письма для сброса пароля выводятся
в серверный журнал; доставка на настоящий email без SMTP не включена.
Уведомления в кабинете работают без SMTP; отправка на почту включается отдельно
и учитывает выбор пользователя в профиле.

Оплата отключена без ключей своего магазина ЮKassa и `PAYMENT_RETURN_BASE`.
Сначала проверяйте тестовыми ключами. В кабинете ЮKassa подключите уведомления
на HTTPS-адрес `/payments/webhook/`. Уведомление само не подтверждает оплату:
сервер отдельно запрашивает статус в API и проверяет сумму, валюту и номер заказа.
Возвраты, автоплатежи и подписки не входят в модуль. Заказ с начатой оплатой
нельзя отменить до её разрешения; при сетевом сбое повтор использует тот же ключ платежа.

## Проверки и размещение

`python manage.py test core` проверяет аккаунты, WebSocket, доступы, заявки,
бронирования, заказы, отзывы и обработку ответов платёжного сервиса.
Для нескольких процессов нужен Redis. Для публичного размещения настройте
хостинг/домен, HTTPS, статику и резервное копирование базы и файлов.
`prototype.html` показывается в изолированном iframe: сгенерированный HTML не
исполняется как Django-шаблон и не имеет доступа к аккаунтам приложения.

## Оформление

Кнопки подключённых модулей встроены в главную страницу через `data-app-navigation`.
У старых страниц они добавляются внутрь существующей шапки или основного блока.
Цвета, шрифт и скругления главной страницы записаны в `static/site-theme.css` и
используются в регистрации, профиле, переписке и других страницах. Переходы из
макета разрешены только по серверному списку маршрутов; изоляция HTML сохранена.
